Transport, sockets et socat

La couche transport relie des processus, là où IP relie des machines. Le cours se termine par un atelier socat entièrement annoté.

Ports et modèle client-serveur

  • Un port est un entier de 16 bits (0 à 65535). Ports 0–1023 réservés (privilèges root : SSH=22, HTTP=80), au-dessus libres. Conventions dans /etc/services.
  • Le client initie l’échange et doit connaître IP et port du serveur. Le serveur (démon) attend en boucle.

UDP et sockets

UDP est non connecté, sans garantie de livraison ni d’ordre, avec un en-tête de 8 octets (ports source et destination, longueur, checksum). Adapté au DNS, au streaming, à la VoIP.

Le client est attaché automatiquement à un port libre (>1023) au premier envoi ; le serveur utilise bind(). getsockname() donne l’adresse locale d’une socket.

TCP

  • Mode connecté et fiable : réémissions, ordre, contrôle de flux (fenêtre) et de congestion.
  • Drapeaux : SYN ouverture, ACK acquittement, FIN fermeture, RST rupture, PSH envoi immédiat, URG urgent, ECN congestion.
  • Côté sockets : serveur listen() puis accept() (une socket de service par client) ; client connect() ; fin avec close() ou shutdown().

Handshake en 3 temps

  1. Client → Serveur : SYN
    Seq = A. Le client demande l’ouverture.
  2. Serveur → Client : SYN-ACK
    Seq = B, Ack = A+1. Le serveur accepte et propose sa séquence.
  3. Client → Serveur : ACK
    Seq = A+1, Ack = B+1. La connexion est établie.

Broadcast et multicast

  • Broadcast : IP de diffusion du réseau (192.168.1.255/24) ou MAC ff:ff:ff:ff:ff:ff ; option de socket SO_BROADCAST.
  • Multicast : classe D (224.0.0.0–239.255.255.255). Le TTL fixe la portée (0 hôte, 1 sous-réseau, <32 site). Le récepteur rejoint un groupe via IP_ADD_MEMBERSHIP ; IP_MULTICAST_LOOP règle la boucle locale.

Atelier socat

socat établit un transfert bidirectionnel entre deux adresses (flux, sockets, processus). Syntaxe : socat ADRESSE1 ADRESSE2.

TCP

Serveur TCP multi-clients

$socat TCP-LISTEN:1234,fork STDIO
  • socatRelie deux flux de données dans les deux sens.
  • TCP-LISTEN:1234,forkTCP-LISTEN : socket serveur. 1234 : port d’écoute. fork : un processus fils par connexion, donc plusieurs clients.
  • STDIOClavier et écran du terminal.

Client TCP

$socat STDIO TCP:192.168.1.15:1234
  • socatRelie deux flux de données dans les deux sens.
  • STDIOLe terminal est la première extrémité.
  • TCP:192.168.1.15:1234TCP : connexion vers l’adresse 192.168.1.15, port 1234.

UDP, broadcast, multicast

Serveur UDP

$socat UDP-LISTEN:1234,fork STDIO
  • socatRelie deux flux de données dans les deux sens.
  • UDP-LISTEN:1234,forkReçoit des datagrammes UDP sur le port 1234 ; fork gère chaque correspondant dans un fils.
  • STDIOAffiche ce qui arrive et envoie ce que vous tapez.

Client UDP

$socat STDIO UDP:192.168.1.15:1234
  • socatRelie deux flux de données dans les deux sens.
  • STDIOTerminal.
  • UDP:192.168.1.15:1234Envoie les datagrammes vers cette IP et ce port.

Émission en broadcast

$socat STDIO UDP-DATAGRAM:192.168.1.255:1234,broadcast
  • socatRelie deux flux de données dans les deux sens.
  • STDIOChaque ligne tapée est envoyée.
  • UDP-DATAGRAM:192.168.1.255:1234,broadcastUDP-DATAGRAM : datagrammes vers une adresse arbitraire. 192.168.1.255 : adresse de diffusion du /24. 1234 : port. broadcast : active l’option SO_BROADCAST, sinon le noyau refuse.

Récepteur multicast

$socat UDP-RECVFROM:1234 ,reuseaddr ,ip-add-membership=224.1.0.1:0.0.0.0 ,fork STDIO
  • socatRelie deux flux de données dans les deux sens.
  • UDP-RECVFROM:1234Reçoit un datagramme UDP sur le port 1234 et mémorise l’émetteur pour répondre.
  • ,reuseaddrAutorise plusieurs récepteurs sur le même port (SO_REUSEADDR).
  • ,ip-add-membership=224.1.0.1:0.0.0.0Rejoint le groupe multicast 224.1.0.1 sur l’interface 0.0.0.0 (interface par défaut).
  • ,forkUn fils par émetteur.
  • STDIOAffichage des messages reçus.

Les options accolées à une adresse sont séparées par des virgules ; elles sont ici découpées pour être expliquées.

Redirection vers des processus

Serveur d’écho

$socat TCP-LISTEN:1234 ,reuseaddr ,fork EXEC:cat
  • socatRelie deux flux de données dans les deux sens.
  • TCP-LISTEN:1234Écoute TCP sur le port 1234.
  • ,reuseaddrRéutilise le port immédiatement après un arrêt (évite « Address already in use »).
  • ,forkPlusieurs clients simultanés.
  • EXEC:catLance le programme cat ; son entrée et sa sortie sont reliées à la socket, qui renvoie donc tout ce qu’elle reçoit.

Redirection vers un shell

$socat TCP-LISTEN:1235,fork SYSTEM:'while read line; do echo $line; done'
  • socatRelie deux flux de données dans les deux sens.
  • TCP-LISTEN:1235,forkÉcoute sur le port 1235, un fils par client.
  • SYSTEM:'while read line; do echo $line; done'SYSTEM : exécute la commande via /bin/sh. Ici une boucle qui relit chaque ligne et la réaffiche.

Dangereux sur un réseau réel : tout client peut déclencher des commandes. À réserver aux tests locaux.

Autres outils de débogage

Capturer le trafic UDP

#tcpdump -i eth0 -X -vvv udp
  • tcpdumpAnalyseur de paquets en ligne de commande.
  • -i eth0Interface à écouter.
  • -XAffiche le contenu en hexadécimal et ASCII.
  • -vvvNiveau de détail maximal.
  • udpFiltre : uniquement le protocole UDP.

Aussi : netstat -aup ou ss (sockets ouvertes), strace -e trace=network,read,write, wireshark.

Envoi rapide avec netcat

$echo "test" | netcat -u localhost 3000
  • echo "test"Produit le texte à envoyer.
  • |Redirige la sortie vers l’entrée de la commande suivante.
  • netcatClient réseau minimal.
  • -uUtilise UDP au lieu de TCP.
  • localhost 3000Hôte et port de destination.
